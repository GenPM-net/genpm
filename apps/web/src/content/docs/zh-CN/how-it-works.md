一个 GenPM 包由三层组成，它们一起交付并固定在同一个提交上：

| 层 | 内容 | 放置位置 |
|---|---|---|
| **代码** | 模块的源代码 | `d`，例如 `src/lib/auth/` |
| **上下文** | 给 AI 智能体的规则（`x`） | `<d>/AGENTS.md`，以及带作用范围的 IDE 规则文件 |
| **连接** | 模块需要的 MCP 服务器（`m`） | `.mcp.json`、`.cursor/mcp.json`……仅在你同意后写入 |

## 注册表只存储元数据

注册表索引清单并指向 Git。安装时，CLI **直接从 Git 托管方**下载确切提交（`c`）的代码并进行验证：`git rev-parse HEAD` 必须等于 `c`，且每个文件都必须与该提交的文件树一致。

## 先计划，再执行

`plan()` 从不写入你的项目。它解析依赖、下载到全局缓存并扫描文件。`apply()` 通过日志写入：任何一步失败，都会全部回滚。

## 绝不运行脚本

GenPM 没有生命周期脚本，包里的任何东西都不会在你的机器上运行。会被其他工具自动执行的文件（`postinstall`、`.npmrc`、`.envrc`、`.vscode/tasks.json`……）会被拒绝。
